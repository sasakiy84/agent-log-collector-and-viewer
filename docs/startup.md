# 起動と受信キュー

HTTPは受信キューの準備後に待ち受けを開始します。表示用DBのスキーマ更新・過去データの整備はその後に進めるため、この処理中もOTELを受信できます。ログインと静的画面はすぐに利用でき、セッションの閲覧は表示用DBのスキーマと読み取り接続の準備後に利用できます。

受信したログ・トレース・メトリクスは、形式を確認してから別のSQLiteファイルへ保存し、確定後に成功応答を返します。表示用の解析・検索索引・集計は非同期で反映されます。停止・強制終了後は未処理分から再開し、表示用DBへの確定直後に止まっても、同じイベントIDの再処理で重複を防ぎます。

過去データの整備はチェックポイント付きのバッチで進み、バッチ間で書き込み接続を解放します。整備中の表示には、まだ更新されていない結果が含まれることがあります。アーカイブ操作は整備の完了を待ち、未反映の受信データがあるセッションのアーカイブ作成・削除は待ちます。他のセッションや既存ジョブのキャンセル・容量回収は、無関係な受信待ちに妨げられません。

## 保存先

`--db /data/agentlog.db` の場合：

| ファイル | 用途 |
| --- | --- |
| `/data/agentlog.db` | 原本イベント、表示用データ、検索索引、集計 |
| `/data/agentlog.db.ingest.db` | 未処理の受信データ、監視ファイルの取り込み履歴 |

両方のDBとSQLiteのWALファイルは同じ永続ボリュームに置きます。既存のCompose設定では`/data`に保存されます。バックアップ対象にも受信キューを含めてください。

受信キューの未処理データの上限は256MiBです。ファイル取り込みは合計128MiBまでに制限し、残りをライブOTEL受信用に確保します。上限や書き込みエラーではOTELに503を返し、成功したことにはしません。ローカルのファイル監視は空きができるまで待ち、HTTPのファイル取り込みも`Retry-After`に従って同じバッチを再送します。処理済みのキューレコードは削除し、空きページを再利用します。

## ファイル監視

一度正常に送信したファイルは、再起動しても未変更なら読み直しません。ファイルの識別情報・サイズ・更新情報、取り込み設定、Copilotの先行ジャーナルを記録します。途中でファイルが変わった場合や送信に失敗した場合は完了扱いにせず、次回に再確認します。

変更されたファイルは既存のパーサーで読み直します。Codexの後から追加される正規メッセージや、Copilotの分割ログの関係を維持するため、単純に末尾だけを読む方式にはしていません。

コレクターに設定した監視は受信キューDBへ履歴を保存します。CLIの`import --watch`はユーザー設定ディレクトリの`agentlog/watch.db`を使い、`--watch-state PATH`で変更できます。

## 状態確認

認証付きの`GET /api/status`で確認できます。

| 項目 | 内容 |
| --- | --- |
| `state` | `migrating`、`preparing`、`ready`、`failed` |
| `pending_batches` | 未反映の受信バッチ数 |
| `pending_bytes` | 未処理データのバイト数 |
| `queue_capacity_bytes` | キューの上限 |
| `import_capacity_bytes` | ファイル取り込みを受け付ける上限 |

データ整備が失敗した場合も、成功応答済みのデータはキューに残します。原因はコレクターのログに出力され、修正・再起動後にチェックポイントから再開します。
